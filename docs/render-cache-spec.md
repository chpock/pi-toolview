# Render cache and UI performance

This specification defines retained layouts and per-frame work. Execution, model content, session data, native hidden/image guards and normalized input remain unchanged. This supplements the summary, Bash, edit, write and shared-frame specifications.

## Work per frame

Pi requests whole-document layout for arbitrary UI updates, including its working animation. Toolview must not rebuild unchanged custom content in those frames. Cache custom summary/Bash/edit/write/user body rows and Bash geometry/expandability separately from transcript separation. Neighbor separation uses cached content metadata; an eligible Bash card's existence/multiline classification never requires formatting its output. For edit/write cards, read an exact existing layout or perform uncached validation-only classification (exact inline heading height, multiline frame class); a retention miss must not rebuild/highlight/paint the diff merely to determine separation. This introduces no additional retained data or cache policy. Record child positions on attachment/initial traversal, with an O(1) position check and lazy repair after structural changes, instead of a fresh sibling index search per rendered call.

Two independent LRU pools retain custom layouts: ordinary views default to 8 MiB, Bash cards, actual edit-diff frames and successful write frames default to 128 MiB. Each component retains at most its latest custom layout width/state across both pools. Width changes rebuild that layout once, not on every frame. Preserve safe actual-width bounds and click coordinates rather than returning old wider rows. No width-history cache, cache-maintenance polling, debounce or suppression of host frames/streaming. The sole bounded, execution-only animation clock is specified below. Unknown self-render visibility continues to be checked at the actual width. One proven exception is the stock Pi edit renderer, identified each visit by exact call/result function identities from the public SDK factory, the verified component contract and a current plain call Box with stock render/clear/addChild methods: it supplies a heading, so custom edit summaries/cards and their spacing need no native row construction. A name alone never qualifies. Native overrides, expansion, images/hidden guards, custom/mixed/missing renderer getters and malformed fallback retain native behavior. No visibility/height retention layer is introduced; existing layout row counts/classification serve spacing. Completed compact rows without an outside separator are returned directly rather than copied.

Cache hits are not free whole-document frames: Pi still assembles/traverses its transcript, unknown self renderers may perform native visibility work, and separator/spinner composition may allocate arrays. Native updates, edit preflight and selection rendering also remain host work. Cold/width/theme builds prepare full required content by design; no off-screen/source-context shortcut or total-process-memory guarantee is implied. See [architecture](architecture.md#cache-separation-and-animation) for the common rendering boundaries.

### Main input exclusion

The stock main editor is not a transcript-layout cache consumer. Each render projects already-rendered native visible rows into the shared user frame; no draft strings, paste maps, providers or editor layouts enter either LRU. Its weak adapter metadata records only current native width/mouse offset and a call-local border packet. Native wrapping/rendering and working-status animation remain host work; no Toolview editor timer, invalidation subscription or warm-frame zero-work claim is introduced. Off/on preserves the same edit engine rather than exchanging text with a replacement. See the [editor contract](card-frame-spec.md#main-input-editor).

## Execution spinner

Use one adapter-owned 100 ms interval (at most ten animation render requests per second, independent of the number of running tools), created only when an attached, visible compact call is rendered after actual execution has started. Argument streaming, completed/history calls, zero-width or native-zero-row calls, expanded/native/image tools, and default Bash/edit/write cards start no clock. There is no idle/background housekeeping interval. The timer is unreferenced so it cannot keep the process alive.

Keep only weak references to the small set of running painted calls. Tick checks inspect that set and its recorded ancestor attachment edges, not the full transcript. Hidden/ineligible or detached calls are removed on render/tick; final results and expansion remove them immediately through native UI-update wrappers. Stop and clear the interval when the last call leaves the set. Off, failure, shutdown and reload also stop it and clear animation state. Renderer replacement is recognized using the stable reference's public children, without receiver probing or private input hooks.

Compose the current first-row glyph outside the retained logical layout. Cached rows keep fixed prefix-offset metadata only, never a frame, node, timer or callback. Advancing a frame calls ordinary `requestRender()` once, without globally invalidating native/custom content. With retained layouts, ticks rebuild no argument formatting, wrapping or neighbor metadata. Cache zero/admission-skip limitations remain unchanged. Starting execution changes only the leading glyph and does not itself discard the cached logical summary; the native `markExecutionStarted()` UI method still executes unchanged. Partial updates retain the clock; final failures retain normal error color after animation ends.

Verify one shared interval for parallel execution, exact tick/render/build counts, no idle redraws, immediate result/expansion/restore stops, hidden/image/native/zero-width guards, detached subtrees and stable-reference renderer replacement. Actual SDK/CLI controls must prove moving physical screen glyphs, cached work, native partial/full information, cancellation/off/on/reload, raw traffic/session identity and collection of the first installer under an active animation adapter.

## Invalidation and ownership

Use weak component keys for state; the bounded recency list may retain only rendered data/accounting, never a component, parent tree, argument/result object or closure capturing those objects. Invalidate custom layout when Pi updates args/results, sets expansion or invalidates the component; mutation inside a reused argument/result object is supported through those existing host methods. Edit/write layouts retain rendered rows/frame classification only, use the same argument/result/expansion/width/theme/`cwd` invalidation, and perform no custom syntax highlighting or diff wrapping on warm frames. User layouts use the ordinary bounded LRU, with weak user-component state and guards for width, theme/paint callbacks, text, padding, native Markdown-child identity/theme/transformers. Native `rebuild`, `setOutputPad` and `invalidate` discard their custom layouts; all native methods still execute. Warm user frames call neither the native renderer nor its Markdown transformations. Native user selection/copy may independently render Markdown, outside Toolview's cached-frame work. Retain native method execution and restore only Toolview-owned wrappers on off/failure/shutdown/reload. State/width/theme-identity guards also cover direct field replacement, status/expansion changes, and Bash command/description/workdir/context changes. Arbitrary silent mutation of nested JSON without a host update/invalidate is outside the renderer contract.

The cache is runtime-local. Clearing replaces its weak state map and empties recency/accounting; off/failure/shutdown do the same. There are no finalizers, GC polling, subscriptions or retained old roots. Collected component keys cannot be kept alive by the recency list. Orphan rendered values may occupy the bounded LRU until ordinary eviction or explicit clear; this is deliberate bounded cache retention, not unbounded node/session retention.

## Memory bounds and controls

Default retained-layout budgets: **8 MiB ordinary** and **128 MiB cards**, each with a maximum of **2048 entries** (4096 aggregate). These are independent budgets/recency lists, not preallocated memory or a shared allowance. Card admission cannot evict ordinary data and vice versa. The card pool contains default Bash frames, collapsed or expanded, successful framed edit diffs and write source/diff frames. Compact Bash/edit/write, precompletion/failed edit/write summaries, edit headings without diff, native edit/write fallback rows and all user-message layouts remain ordinary. Classify the materialized presentation rather than the tool name. A tool's weak state records its pool so updates, kind/lifecycle changes and width replacement drop the previous entry from the correct pool; no component owns retained entries in both pools at once. One latest custom body per component is retained. Estimated bytes use `512 + sum(64 + 2 * row.length)`: fixed entry/row overhead plus two bytes per retained string code unit (including ANSI), conservatively also allowing for row-array references. These are extension cache accounting estimates, not exact V8 heap allocation. Do not retain duplicate raw output, original args/results or a multi-width history in the cache. Evict least-recently-used data on admission or limit reduction; an entry larger than the entire budget is not retained. Entry eviction clears its rendered value even if a live weak-key state still points at its accounting record. Limit zero disables retention; no promise of cache-hit performance in that explicit mode. No unbounded counter logs or per-frame memory sampling.

Optional commands, with no persistent settings writes:

- `/toolview cache`: show `ordinary` and `cards` snapshots (estimated bytes, budget, entries, hits/misses/builds/evictions/admission skips), with existing top-level numeric fields equal to the sums of both pools. Default aggregate budget is **136 MiB**, maximum configurable aggregate **192 MiB**. Current process heap usage is explicitly labeled **whole Pi process**, not Toolview attribution. Sample process memory only on demand. Lookup misses and completed body builds are distinct counters: metadata-only neighbor measurement can miss an evicted edit without constructing/admitting another body.
- `/toolview cache clear`: release both pools and weak state; subsequent frames rebuild on demand.
- `/toolview cache limit <MiB>`: set only the ordinary runtime budget, inclusive range 0–64 MiB; lowering it evicts ordinary data immediately without affecting cards.
- `/toolview cache cards limit <MiB>`: set only the Bash/edit-diff/write-card budget, inclusive range 0–128 MiB; lowering it evicts card data immediately without affecting ordinary views.
- `--toolview-cache-mb <MiB>`: initial ordinary budget, default 8, range 0–64.
- `--toolview-card-cache-mb <MiB>`: initial card budget, default 128, range 0–128. Invalid launch values warn and use the corresponding default; invalid commands leave limits unchanged. These controls write no settings and survive off/on/session replacement within the loaded extension; reload resets to launch/default values.
- A zero limit disables only that pool. To disable all custom retention, set **both** limits to zero; the old single-budget zero flag no longer disables card retention. Whole-cache clear/off/failure/shutdown still release both pools.

Keep `/toolview on|off|status`, policy flags and non-TUI behavior. Memory control does not cap model/tool data or claim to free host-owned/native rendering memory. Cache clear does not itself recursively invalidate native tool contents.

Successful file cards show all available changes/source without a Bash-like preview or compact-text cap. Plain write bodies share the linear wrapping/highlighting path but calculate no Multiply colors. Validation-only write measurement checks source availability and metadata without materializing code, admitting another body or retaining classification. Missing diff uses submitted content; producer-side omissions cannot be recovered. See the [write contract](write-card-spec.md).

## Output preview

Collapsed Bash wrapping stops as soon as an eleventh visual output row proves overflow; it does not build all hidden visual rows. Use the first ten rows, then remove their trailing whitespace-only rows before the overflow hint without searching hidden rows for replacements. Preserve interior preview blanks and all expanded interior blanks, grapheme/tab/control safety and the expansion hint. The Bash spec's exact separated terminal duplicate exit-footer removal precedes wrapping/overflow and does not infer status or rewrite raw data. Expanded output is built only on demand and cached subject to the same budget. Oversized uncached layouts and changing large results can still require transient work/memory; the budget bounds retained extension cache, not total Pi heap or pathological raw tool data. Favor bounded preview work over exact hidden row counts: do not compute or display such a count.

## Verification

Follow the shared [testing and coverage guide](testing.md). Counters must prove unchanged frames do no custom body builds, updating one tool rebuilds only that tool (including reused mutable objects), cached neighbor checks do not rebuild earlier Bash output, and resize/theme/expansion/invalidate cause only necessary work. Test budget/entry limits, eviction clearing values, zero/admission skips, limit reduction/clear, weak ownership structure, restore/later owners, shutdown/reload and native renderer-mode replacement. Use actual SDK and real CLI captured traffic, native/off/replay controls and physical width/click/color checks; never replace strict body/model/session equality with approximate performance assertions. Optional diagnostic snapshots must have finite monotonic counters and accurately labeled estimated cache versus whole-process memory. Record observable work counts, not timing-only claims. Keep source-bound experiment/review packets under gitignored `.test-artifacts/`; do not turn historical run totals or superseded budget decisions into current guarantees.
